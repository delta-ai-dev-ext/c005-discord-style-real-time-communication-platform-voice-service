# ADR-001: Stateless Voice Service with LiveKit Cloud

## Status
Adopted

## Context
The `voice_service` manages voice/video channels for the community platform. An in-house SFU (Selective Forwarding Unit) would require stateful media sessions and UDP port ranges, which conflicts with the platform's mandated **stateless container replicas** model. The backend must remain in control of *who* may join and *with which capabilities*, but must not own the media transport itself.

## Decision
We use **LiveKit Cloud** as an external WebRTC SFU provider. The `voice_service` remains a **stateless authorization and coordination service**:

1.  **Token Minting:** `voice_service` mints short-lived LiveKit access tokens locally (no network call) using the LiveKit API secret. It maps `community_service` access (`can_connect`, `can_speak`, `can_video`) to LiveKit grants.
2.  **Stateless Room State:** Live room state (participants, connections) is owned by LiveKit and queried on demand via the `RoomServiceClient` (server API). No PostgreSQL is used.
3.  **Moderation Enforcement:** Moderation actions (`member_kicked`, `member_banned`, `member_timed_out`) are propagated asynchronously via the `community_events` Kafka topic. `voice_service` acts on these events by removing participants or revoking permissions via the LiveKit server API.
4.  **Webhooks:** LiveKit pushes events (`participant_joined`, `participant_left`, `room_finished`) to `voice_service` via a signed webhook (JWT + body SHA-256), which is used to drive session and participation metrics.

## Consequences
*   **Positive:** Fully stateless replicas (horizontal scaling trivially). Media flows directly between clients and LiveKit Cloud; the backend never relays media.
*   **Positive:** LiveKit is a managed service (no infrastructure maintenance for the SFU).
*   **Negative:** We are dependent on LiveKit Cloud availability and pricing; concurrent participant quotas must be sized from pilot data (rooms capped at ~50 by the backend).
*   **Negative:** Requires a `readyz` probe that checks Kafka consumer assignment to prevent processing lag during scaling events.
